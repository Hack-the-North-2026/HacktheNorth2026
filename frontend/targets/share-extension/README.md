# Native Share Extension Target

The iOS Share Extension is generated by our local Expo config plugin. It accepts
one image, uploads directly to the identify API with `origin=ios_share`, polls
until the job finishes, and schedules a local notification that opens the job.
It does not use an App Group or Apple push notifications.

## iOS Setup

- Plugin: `frontend/plugins/with-direct-share-extension.js`
- Native controller: `frontend/targets/share-extension/ShareViewController.swift`
- Extension bundle: `com.fitstealer.app.ShareExtension`
- Supported payload: one image

Before building, expose the backend at an HTTPS URL and set it in the prebuild
environment:

```bash
EXPO_PUBLIC_API_BASE_URL=https://your-backend.example npx expo prebuild --clean --platform ios
```

Open the generated workspace in Xcode, select the same Personal Team for the app
and `FitStealerShare` targets, then run on the phone. Open Fit Stealer once and
grant notification permission before testing the share sheet. This does not run
in Expo Go.

Keep the share window open until it says the upload is complete. Video is
intentionally not advertised until the Stage 3 video ingest contract exists.
Apps that only share a webpage URL will not show Fit Stealer as an image
destination.

## Android Setup
- Android `RECEIVE_SHARING_INTENT` intent filter configuration in `AndroidManifest.xml`.
